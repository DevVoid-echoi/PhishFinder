# Development Notes

Known limitations and design decisions found while building phase 1.
These feed the "Known limitations" section of the README.

## Known limitations

### Parser (`app/parser.py`)
- **Not every shared-hosting platform is a PSL private suffix.** `abc.wordpress.com` resolves to `wordpress.com`, while `evil.github.io` correctly resolves to `evil.github.io`. Relevant for the Tranco allowlist (step 8e); covered by a test in `tests/test_extras.py` that records the current behavior.
- **Bundled Public Suffix List snapshot.** `tldextract` runs offline (`suffix_list_urls=()`), so new suffixes only arrive when the library is upgraded.
- **Single-label hosts.** `localhost` gives `registered_domain='localhost'` and an empty suffix.
- **Port is ignored.** `urlparse` moves the port to `parts.port`; it is not stored. Possible future rule: non-standard port on a brand-like domain.
- **IDNA 2003 vs browsers.** Python's `idna` codec implements IDNA 2003: `straße.de` becomes `strasse.de`, while browsers (UTS #46) produce `xn--strae-oqa.de`. Rare, but a possible Python/JavaScript mismatch for step 12; the `idna` package (IDNA 2008) would remove it.
- **Unknown schemes are not flagged.** `ttps://`, `javascript:`, `data:` pass through; `check_no_https` only fires on exactly `http`. Found when a typo (`ttps://`) in a test still passed.

### Heuristics (`app/heuristics.py`)
- **Keyword matching is substring-based.** `login` in `github.com/login` adds 10 points to a legitimate page (low impact, stays below the threshold).
- **Weights are initial estimates**, not tuned on data yet (learned from data in step 9).

### Lookalike detection (`app/lookalike.py`)
- **Short brands (<= 5 chars) only match as separate tokens.** Fixes false positives such as `zalora.com`, `tikitaka.com`, `bidvietnam.com`, but `momoshop.com` is no longer caught. Accepted trade-off: fewer false positives for some missed lookalikes.
- **Aliases also match only as tokens.** `vcb-xacthuc.com` is caught, while `vcbs.com.vn`, `tcbs.vn`, `fbi.gov` are not flagged. An alias glued to another word is missed.
- **Typos on short names slip under the similarity threshold (0.85).** `shoppe` vs `shopee` = 0.83, `mono` vs `momo` = 0.75; both score 0.
- **Brand in userinfo is only caught by the `@` rule.** `vietcombank.com.vn@evil.com` scores 30; the lookalike rule does not inspect the part before `@`.
- **Unicode lookalikes use a small confusables table.** Punycode labels are decoded and Cyrillic/Greek look-alike letters are mapped to Latin, so `mоmо.vn` (Cyrillic о) scores 65. The full Unicode confusables list has thousands of entries; characters outside the table are missed.
- **Brand data is maintained by hand** in `data/brands.json`. A wrong or missing official domain flags a legitimate site; aliases are only added once seen in real phishing samples.

### Lists and evaluation data (`app/lists.py`, `scripts/`)
- **Few Vietnamese-targeted pages in fresh feeds.** About 78 of 155,901 phishing.army domains look Vietnam-related (`.vn` or a Vietnamese brand). Recall on Vietnamese phishing will rest on a small sample; manually collected links (`data/samples_phishing.txt`) matter most.
- **Labels are noisy.** Feeds contain dead pages and likely mislabels (e.g. `account.esms.vn`); hand-check 50 random entries per set before measuring.
- **Daily snapshots miss short-lived entries.** phishing.army refreshes every 4 hours; an entry added and removed within a day is never recorded.
- **Domain-list entries become `http://<domain>/`.** Every such phishing sample triggers `check_no_https` and none trigger path rules (keywords, long URL). Benign entries must be built the same way, or the evaluation and the weights learned in step 9 will reward the scheme instead of real signals.
- **The benign test set is too small for the red target.** With 30,000 Tranco domains, the split (50% train, 25% validation, 25% test) leaves 7,503 test pages; one red false alarm moves the rate by 0.013%, so the 0.05% target cannot be measured. About 80,000 benign pages (Tranco up to rank ~90,000) are needed for a 20,000-page test set.
- **The benign set changes with every Tranco list.** Runs on lists 262W9 and 746PX sampled different test pages (red false alarms 0.013% vs 0.000%). Pin one list ID while comparing rule changes, and only switch lists deliberately.
- **The time split is meaningless until several days of data exist.** On the first day every entry has the same `first_seen`, so the "newest 30%" is just the alphabetical tail.
- **Low recall on random-looking domains is expected.** Most phishing.army entries are random strings on cheap TLDs (`*.sbs`, `*.top`); they score 25 (TLD 15 + HTTP 10), below the yellow threshold. Domain age and TLS (step 8) and learned weights (step 9) target these.
- **The Vietnamese subset is defined by `.vn` suffix only**, so it does not depend on the rules being measured, but it misses Vietnamese-targeted pages on other suffixes (`vcb-xacthuc.com`). Manually collected samples would give a better Vietnamese set.
- **Most fresh phishing fires no informative rule.** On the first fresh test set, 77.8% of phishing URLs fired nothing besides the HTTP rule, exactly like 98.0% of benign pages; no reweighting can separate them. The rule layer caps detection at about 22% on these feeds.
- **The cheap-TLD rule is too common on legitimate sites to stand alone** (about 1.4% of benign pages, above the 0.5% yellow target), so a learned model cannot warn on it by itself.
- **Fresh Vietnamese phishing is almost absent:** 4 to 7 `.vn` entries in the fresh test set, so the Vietnamese detection rate is not yet meaningful.
- **Benign pages have no paths** (0 of 80,000) while 350 phishing entries do, so path-based rules (keywords in path, long URL) can learn leaked weights; `benign_private.txt` from real browsing would fix this.
- **PhishVN (NCSC-verified phishing aimed at Vietnamese users) is old:** dated 2020-02 to 2025-02-18, after which the NCSC feed published nothing. It measures whether the rules recognise Vietnamese *kinds* of phishing, not fresh phishing; most domains are dead, so domain age and TLS cannot be measured on it. Almost every URL is a bare domain in both labels, so it has no path shortcut.
- **PhishVN scenarios are inferred by its authors from brand tokens in the URL,** so "bank" means "the URL names a bank". A bank phish without a bank name lands in "other" (83% of rows), and per-scenario detection overstates how well brand rules cover each sector.
- **The rule layer catches 6.0% of PhishVN test phishing (10.3% on train).** The test split is the newest; the drop shows phishing moving away from what the rules look for. Only 28% of NCSC phishing fires an informative rule.
- **Telecom and conglomerate brands are not protected** (Viettel, VNPT, MobiFone): their subsidiaries use dozens of legitimate domains (`viettelpay.vn`, `vnpt-invoice.com.vn`), so a name match alone cannot tell them from `lapmangvnpttelecom.xyz`. Protecting them needs their full domain lists or a server signal (domain age).
- **Scam sites outside the URL rules' reach:** NCSC also lists gambling, adult and fake-investment sites (`tructiepbongda`, `dinotube`, `raidenbo`, `exness`) whose names imitate no brand. Some labels are disputed (`exness.com` is a real broker; `facebook.com/<page>` rows are pages, not domains).
- **`momo` inside a word** (`momofhd.com`, `lotomomo.com`) is still missed by the whole-token rule for short brands.
- **Rules that never fire in training get weight 0** in the learned model (`check_ip_host`, `check_shortener`, `check_at_symbol`), i.e. they stop affecting the score while their reasons are still shown.
- **URL blocklist matching ignores scheme, host case and trailing slash, and drops an appended query** when the listed URL has none. A listed URL that carries its own query still needs that exact query, so attackers can evade it by changing parameters.

### Reputation (`app/online.py`)
- **No domain age for `.vn`:** there is no RDAP service for the TLD, so Vietnamese domains rely on the text rules only.
- **Hacked old sites have a normal age.** `aaghazedosti.com` (registered 2022) hosts phishing; domain age only catches newly registered domains.
- **Phishing domains disappear quickly.** `006901.com`, collected on 2026-10-21, returned 404 (no longer registered) a day later; `96fj.top`, registered on 2026-10-21, was gone by 2026-10-26. Look up the step 9.3 sample soon after collection.
- **RDAP servers rate-limit and reset connections** (Verisign reset one request, then answered). The API in step 7 must cache results instead of querying on every request; any failure already gives no finding.
- **TLS: free certificates are not a signal; new ones are.** Only certificates issued in the last 7 days score (20). First live check: 4 of 15 fresh phishing hosts had certificates issued one day earlier.
- **TLS: invalid certificates score 30,** which also flags legitimate sites with expired or misconfigured certificates.
- **TLS: slow worst case.** About 10 s per host (2 addresses x 5 s timeout), and DNS resolution has no timeout of its own; the API (step 7) must cache results or run the check off the request path.
- **Server-side checks can be cloaked.** An attacker can answer the server differently from victims (by IP, region or time). Rules that run in the browser are not affected; no single server-side signal is trusted alone.
- **`None` does not say why.** Not registered, unsupported TLD and network errors all give no finding by design; call `fetch_json(rdap_url(...))` directly when debugging.

### False alarms seen in the first measurements (fix in step 9, measured on the validation set)
- **Official domains in other countries:** `facebook.de`, `thefacebook.com`, `shopeepay.com.br` are flagged as impersonation because `brands.json` lists only the main domains.
- **Brand contained in a longer real name:** `otpbank.ru` (a real bank) contains `tpbank` and scored red (60).
- **Three-letter names vs four-letter brands:** `bid.cars`, `mom.gov.sg`, `alo.rs` reach similarity 0.857 with `bidv`, `momo`, `zalo`, above the 0.85 threshold.
- **Alias as a whole label:** `fb.gg` matches the `fb` alias.
- **Legitimate IDN domains** (Thai, Russian) score 35 from punycode (25) plus HTTP (10). The 10 sites still flagged in the Tranco top 10,000 are all IDN domains; with `https://` they drop to 25. Punycode alone is a weak signal.
- **The allowlist cannot fix these on the benign test set** by design: it covers ranks 1-10,000 while the benign set uses 10,001-40,000.

### API (`app/main.py`)
- **No rate limiting in the app.** CORS only stops other web pages; scripts can call the API freely, so rate limiting belongs at the API Gateway (step 14). Until then, keep the server bound to `127.0.0.1`.
- **The cache lives in process memory.** It is lost on restart and not shared between instances (e.g. Lambda cold starts); acceptable at beta scale.
- **Reports are only written to the log** (`REPORT verdict level host version`); they must be read by hand daily in step 15 and moved to a database later.
- **TLS worst case is about 10 s per uncached host,** which the extension must tolerate (show the local result first, update when the server answers).
- **The AI budget is counted per process.** `DailyBudget` (300 calls a UTC day by default, `DAILY_AI_LIMIT`) lives in memory: two server processes allow twice as many calls, and a restart resets the count. The prepaid credit balance is the hard cap.
- **`/v1/analyze-page` can take up to about 35 s** for an uncached page: up to 15 s to download it, then two Claude attempts of up to 10 s each. The extension must show the URL result first.
- **The page cache key is a SHA-256 hash of the URL.** It keeps URLs out of memory dumps of the cache, but it is not anonymous: anyone who guesses a URL can hash it and check whether it was analysed.

### Page analysis (`app/page_features.py`, `app/page_analysis.py`)
- **Only the HTML as downloaded is read.** Text and forms built by JavaScript are invisible, and so is anything hidden with CSS that a person would not see (it is read as if visible).
- **Cloaking:** a phishing page can recognise a cloud server and serve harmless content to it.
- **Late warning:** the result arrives after the page has loaded, so the user may already be typing.
- **News pages with a login box** whose title names a bank ("Vietcombank warns of scams") would fire `page_brand_login`; measure how often on real pages before changing the rule.
- **Forms submitted by JavaScript** have no `action`, so `page_form_external` misses them.
- **Points are starting values** (50 / 20 / 20 for rules, 40 / 30 / 10 for AI) until the page measurement and the calibration rerun.

### SOC alerts (`app/alert.py`)
- **Alerts in production come only from user reports,** so their only observable is a hostname and `risk_score` is `null`; `to_alert` on URL results is used from the command line for now.
- **No deduplication.** Ten users confirming one domain give ten alerts, and `/v1/report` has no authentication, so a script could flood the log until the gateway rate limit exists.
- **Field names are our own,** not Elastic Common Schema; a SIEM needs a small mapping until they are renamed (`url.full`, `threat.technique.id`).
- **`status` is always `new`:** there is no workflow behind it yet.

### Short-link expansion (`app/page_fetch.py`, `/v1/expand`)
- **Only HTTP redirects are followed** (301, 302, 303, 307, 308). Redirects done with JavaScript or `<meta http-equiv="refresh">` end the chain early, so `final` can be an intermediate page.
- **HEAD and GET can differ.** Some shorteners answer HEAD with 405 or a different target; HEAD is kept because it downloads no page body.
- **Cloaking:** a shortener or landing page can send the server (data-centre IP, no cookies) somewhere harmless while victims get the phishing page.
- **`SHORTENERS` lists 8 international services only;** Vietnamese shorteners are not covered yet, and any other link is refused with 400.
- **The expansion request is visible to the shortener,** which learns that someone checked the link (not who: the request comes from the server).

## Decisions
- **Reasons and level names are in English** (`dangerous`, `suspicious`, `likely_safe`), unlike the Vietnamese examples in the guide. Any new code (alerts, email analysis) must use `score_to_level()` instead of repeating the thresholds.
- **TPBank:** only `tpb.vn` is listed as official (verified); `tpbank.vn` is intentionally not allowlisted.
- **Single parser path.** `tldextract` is a required dependency; the guide's hand-written fallback was dropped so results cannot differ between machines.
- **Test runner is pytest.** Install with `pip install -r requirements-dev.txt`, run with `python -m pytest` (avoids picking up a global pytest). All tests use pytest style (plain `assert`, `parametrize`, fixtures); the last unittest-style file was converted in step 8d.
- **Dependencies are split and list top-level packages only.** `requirements.txt` holds runtime packages (`fastapi`, `tldextract`, `uvicorn`); `requirements-dev.txt` adds test tools (`pytest`, `httpx2`). `pip freeze` is no longer used, so dev tools cannot leak into the runtime file. Trade-off: transitive dependencies are not pinned; a lock file (pip-tools or uv) would fix this.
- **The production API accepts hostnames only** (`GET /v1/reputation?host=`): the extension strips the URL to its hostname on the user's machine before sending, and the server rejects anything else with 400 (full URLs, IPs, ports, Unicode). Data that is never sent cannot leak through gateway or access logs. The old full-URL `/check` endpoint was removed.
- **HTTP status codes carry meaning:** 400 for a value that is not a valid hostname, 422 for schema errors (missing field, wrong pattern), never 200 with an error body.
- **Endpoints are versioned (`/v1/`)** so old extension versions keep working when the format changes.
- **`/docs` and `/openapi.json` are disabled** unless `PHISHFINDER_DEV=1`; CORS allows only the origins in `EXTENSION_ORIGIN` (empty by default).
- **Logs hold counts, not hostnames,** for reputation lookups: a hostname next to a client IP is browsing history. Reports do log the validated hostname, which cannot inject log lines; `extension_version` is restricted to digits and dots for the same reason.
- **The cache is thread-safe** (FastAPI runs `def` endpoints on worker threads), and domain age is cached per registered domain, so subdomains share one RDAP lookup.
- **External check failures are logged, not swallowed** (`_safe` logs the error type, never the host).
- **`httpx2` instead of `httpx` for `TestClient`.** Starlette 1.8 deprecates `httpx` for its test client.
- **Hostnames are converted to punycode like browsers do**, so the Python core sees the same input as the extension.
- **Deterministic output.** Wherever a set is involved (e.g. the matched alias), pick with `sorted(...)`, so the JavaScript port (step 12) can match the Python results exactly.
- **Evaluation sources.** vn-badsite-filter is frozen since 2025-05 (upstream `api.chongluadao.vn` shut down), so it serves as blocklist (16,843 domains, CC0/MIT) and "old" phishing only. Fresh phishing comes from phishing.army (aggregated, refreshed every 4 hours, free for personal use) and OpenPhish (community feed, full URLs).
- **`data/blacklist_manual.txt` holds 142 domains from Vietnamese advisories** (NCSC, VNCERT/CC, provincial police and finance departments, tax offices, press), reviewed 2026-11-03 from an AI-compiled list of 217. Every kept entry was found on the page it cites (156 of 156 government and press entries were; none was invented). The 61 ChongLuaDao entries, copied by hand from their public list, are kept apart in `data/raw/chongluadao_manual.txt` (59 hostnames, never the parent domain): it is loaded into the blocklist but not committed, because the email of 2026-10-25 promised to follow whichever use ChongLuaDao allows, and committing or bundling it would be redistribution. Left out of it: `cards.vpbank.com.vn` (marked by ChongLuaDao as a suspected false alarm; it is VPBank's own domain) and `vietkey.vn` (Vietkey was real software; the listing says it needs more checking). Left out of the committed list: 7 domains re-registered after the advisory (RDAP; the new owner may be legitimate) and 7 duplicates. Platform subdomains (`hethongnoibo.bio.link`, `vnpttechnology.weebly.com`) are listed as full hostnames, never the platform; no entry is an official, allowlisted, NCSC-certified or benign-set domain. 120 of the domains no longer exist: re-check yearly, because an expired domain can be registered again by someone else. The rule layer alone catches 59 of the 156 (38%).
- **Raw feeds and `data/eval/phishing.csv` are not committed** (personal-use terms, size). `phishing.csv` must be backed up weekly because its `first_seen` dates cannot be recreated. First collection: 2026-10-21, 173,196 entries (all "old" by definition).
- **Tests never depend on downloaded data.** They replace lists with `monkeypatch` and write files under `tmp_path`, so results do not change when the feeds do.
- **`run_rules()` is separate from `analyze()`,** and `analyze(url, use_blacklist=False)` measures the rules alone; the blacklist would otherwise "detect" its own entries.
- **Tests start with empty lists** through an autouse fixture in `tests/conftest.py`, so `analyze()` can consult the real blacklist in production without making tests depend on downloaded data.
- **Benign and phishing entries share one URL form:** bare domains become `http://<domain>/` in both sets, so the scheme carries no label information.
- **Benign pages come from Tranco ranks 10,001-40,000,** never the top 10,000 that will be allowlisted; benign hosts also labelled phishing are dropped. The Tranco list ID is committed in `data/eval/tranco_id.txt`; the derived files are not.
- **Domain age uses RDAP** (JSON over HTTPS, standard library only) instead of python-whois, which failed on every `.vn` domain tested and returned no date for some gTLDs. Any lookup failure gives no finding. First live check: 6 of 8 fresh phishing domains were under 30 days old.
- **TLS check blocks SSRF with an allowlist, not a denylist:** every resolved address must be `is_global` and not multicast (the guide's check let CGNAT `100.64.0.0/10` and multicast through), and the connection goes to the checked IP with the hostname as SNI, which closes the DNS-rebinding gap.
- **No signal subtracts points.** Lookup failures, SSRF refusals and timeouts add nothing; the lowest level is named `likely_safe`, never `safe`.
- **Tests block the network** with an autouse fixture in `tests/conftest.py`: any accidental real request raises `RuntimeError`, which no code path catches, so the test fails.
- **The Tranco allowlist only disables lookalike checks on the registered domain;** subdomain and alias-in-subdomain checks still run. 752 collected phishing entries sit on allowlisted platforms (`eu.cc` 623, `mybluehost.me` 42, `cloudwaysapps.com` 14, `meusitehostgator.com.br` 13, `railway.app`, `gitbook.io`...), where the guide's design would skip every lookalike check (`vietcombank-xacthuc.wordpress.com`: 45 -> 10).
- **Measured benefit of the allowlist:** false alarms among the Tranco top 10,000 drop from 35 to 10 (Tranco 746PX), all of them brands' own foreign or infrastructure domains (`shopee.co.id`, `lazada.sg`, `facebook.net`, `fb.watch`, `cdninstagram.com`). Accepted cost: a few non-brand sites are spared too (`sssinstagram.com`, a third-party downloader).
- **`VERIFIED` (hand-checked after a user report) skips every rule;** the allowlist skips only the domain-level lookalike checks. The blacklist applies to both.
- **Weights are learned with logistic regression on rule sets, not URLs.** About 207,000 URLs collapse into ~33 distinct (rule set, label) groups; training on grouped counts gives the same result thousands of times faster, so 5,000 epochs take 0.1 s.
- **L2 is chosen on the validation split** (0.01 / 0.001 / 0.0001 / 0.00001): the guide's fixed 0.01 pushed rare rules to almost zero (lookalike 0.13). Thresholds are picked on benign validation, with floors of 70 (red) and 40 (yellow).
- **The phishing test set is every entry first seen after the first collection day;** the first day is a snapshot of everything already known and is used for training and validation only.
- **Learned weights are not used yet.** On the fresh test set they detect less than the hand-written points (0.7% vs 1.4%; Vietnamese 0/7 vs 5/7) while both meet the false-alarm targets. `data/weights.json` is not committed until a model beats the hand-written points on validation; rerun in week 6.
- **Tests always use the hand-written points** through an autouse fixture that sets `scorer.WEIGHTS = None`.
- **Feed downloads are bounded and atomic:** 60 s timeout, 20 MB cap, write to `.part` then rename. Each download is retried up to 3 times (waits 5 s, then 10 s) after phishing.army timed out once during the TLS handshake (2026-10-29); a feed that still fails keeps its previous file, so a day with far fewer new entries than usual (normally about 1,500-2,600) means the collection must be rerun the same day.
- **`/v1/expand` takes full URLs, but only for known shorteners** (`normalize_short_url`: http/https, no userinfo, no port, at most 200 characters, host in `SHORTENERS`). A short link's path is the whole link, and it carries no personal data the shortener does not already have.
- **Every redirect hop is checked again** before connecting: scheme (http/https), port (80/443 only) and that every resolved address is public. The connection goes to the checked IP (hostname kept for Host and SNI), so neither a redirect to `169.254.169.254` nor a name that resolves internally, nor DNS rebinding between check and connect, can reach internal services.
- **Limits:** 5 s per request, 15 s overall, 5 hops, HEAD by default, 1 MB body cap and `text/html` only for GET. The response includes the full `chain` and the last `status`; results are cached for 6 hours.
- **Pinned connections override `connect()` with `@override`,** so a misspelled method name (it happened: `connection`) fails at type-check time instead of silently connecting by hostname.
- **A user report is never above `medium` and never reaches the blocklist automatically:** users can be wrong or report a rival on purpose, so a domain is added only after a manual check. `false_positive` reports create no alert.
- **`to_alert` raises `ValueError` on an error result** instead of inventing a `low` alert, which would hide broken input among harmless logs.
- **User reports have `risk_score: null`, not 0:** no score was computed, and a 0 would sort a `medium` alert below every other alert in a SIEM.
- **Alerts go to the log in production** (`ALERT {json}`, one line, shipped to CloudWatch), because a Lambda file disappears on restart. `write_alert` is for local JSON Lines; `alerts.jsonl` is git-ignored since it holds checked domains and URLs.
- **Impersonation (T1656) is keyed on exact rule names,** not a substring match, so a future rule cannot trigger it by accident.
- **Timestamps are UTC,** because a SIEM merges logs from machines in different time zones.
- **Plan step numbers never appear in code, comments or tests;** they mean nothing to someone reading the code. `note.md` is the only place that uses them.
- **TikTok and Snapchat added to `brands.json`** (2026-11-02): TikTok Shop scams target Vietnamese users (`napxutiktok.net`, `tiktokck888.com` in the collected feeds). Official domains are kept to the main ones: `tiktok.com`, `tiktokv.com`, `tiktokcdn.com`, `tiktokshop.com`, `tiktokglobalshop.com` (same registrar as `tiktok.com`), `snapchat.com`, `snap.com` (the `snapchat.com` certificate is issued to Snap Inc. for `*.snap.com`). Validation split: the 5 TikTok/Snapchat phishing entries went from 0 to 5 detected; yellow false alarms rose from 0.180% to 0.205% (4 TikTok infrastructure domains such as `tiktokv-eu.com`, plus `tiktokmod.pro`), red unchanged at 0.005%. Unverified infrastructure domains are not added as official: a wrong official entry would exempt an attacker's domain from every lookalike check.
- **Vietnamese brand and fake-suffix rules were tuned on PhishVN train and checked on validation, then measured once on test** (2026-11-03). Rounds on PhishVN train detection / PhishVN train false alarms / our Tranco validation yellow false alarms: start 213 / 25 / 0.205%; +26 brands and 3-letter brands 317 / **85** / 0.220%; dropping `dichvucong` (a generic word on every provincial portal, 32 false alarms), Viettel, VNPT and MobiFone, and limiting similarity matching to brands longer than 5 characters (`shub` ~ `shb`, `npt` ~ `vnpt`) 303 / 30 / 0.205%; `check_fake_vn_suffix` and banking keywords 340 / 30 / 0.205%. The 80,000-page Tranco set barely moved in the bad round: it holds few Vietnamese sites, so Vietnamese-specific rules must be checked on Vietnamese benign pages.
- **Brands of 3 characters now match** (`MIN_BRAND_LEN = 3`, previously 4, which silently disabled `gdt`), always as whole tokens. Official domains for new brands come from the NCSC trusted-site registry or the Tranco `.vn` top list; `vietbank` was added because `vietbank.com.vn` was flagged as a `vietinbank` look-alike.
- **Calibration rerun with PhishVN (2026-11-05): learned weights still not adopted.** PhishVN train phishing is split by time and registered domain (newest 20% = 529 validation entries, from 2022-08-22; the authors' own validation holds 24). On validation the learned model detects 0.3% of feed phishing and 10.2% of PhishVN against 1.0% and 18.5% for the hand-written points. Tried, all on validation: four L2 strengths (10.0-10.2%), up-weighting PhishVN 10x and 30x (10.0-11.2%), counting each registered domain once (lookalike weight 0.16 -> 1.81, still 10.2%) and choosing the model on PhishVN only (10.2%). Cause: 96% of training phishing is random cheap-TLD domains, so the model ranks a cheap TLD above brand impersonation; keeping yellow false alarms under 0.5% puts the threshold above the cheap-TLD score (1.4% of benign pages have one), which leaves impersonation alone below it. Reweighting cannot change that ranking; new evidence can (server signals, continuous lexical features), or a combination where the learned score can only raise the hand-written one. Per-domain weighting and PhishVN-first selection are not kept in the code: they changed no measured result.
- **`--calibrate` saves weights only if they win on every validation set** (feeds and PhishVN); the rule used to live only in these notes. Validation false alarms are read for the scoring in use, not for a rejected model.
- **Page analysis is two layers:** fixed rules on the HTML (work without the AI), then an AI that only extracts facts into a fixed schema. AI findings only add reasons; nothing removes a rule finding, so a fully manipulated AI cannot lower a warning (tested).
- **Prompt injection defences:** the page sits inside `<page>` tags, every `page` tag the page writes itself is removed (including `< /page>` and `<page id=...>`), the AI output is validated strictly (`parse_ai`: exact keys, known values, types, summary cut to 300 characters), and any failure falls back to the rules with the error type logged.
- **Brands are read from the page title only,** never the body: real shops write "pay with MoMo or Vietcombank". Short names and aliases must be whole words, Cyrillic look-alikes are mapped, but domain homoglyphs (`0` to `o`) are not applied to titles.
- **Only protected brands count for the AI:** every real site "claims to be" itself, so a claimed brand must be in `brands.json`.
- **Password fields are `type="password"`,** not any field whose name contains "password"; OTP and card fields also match the standard `autocomplete` values (`one-time-code`, `cc-number`...).
- **The AI is passed in as `llm_fn`,** so tests use fake answers (no network, no cost) and the provider can change without touching the rules.
- **Page analysis uses Claude Haiku 5.5** (`claude-haiku-5-5`, $0.10 / $0.50 per million input / output tokens; at most about 2,500 input and 500 output tokens, so about $0.0005 per page). Cost is capped twice: `DailyBudget` in code (300 calls a day, about $0.15 a day or $4.5 a month per process) and prepaid credits with auto-reload turned off, so a leaked key can spend at most the remaining balance. Console rate limits (requests and tokens per minute) only stop bursts: 10 requests a minute could still cost about $216 a month. The Spend Limits API is for Claude Enterprise organisations only, not Console accounts. Tests and CI never call the real API; the AI is a fake function there. Free tiers were considered: Gemini's free tier uses submitted content to improve Google's products, which conflicts with sending users' pages.
- **`/v1/analyze-page` is the only endpoint that takes any page URL,** because the user turns deep analysis on in the extension. The `#fragment` is dropped (a browser never sends it to a server either), URLs with a user name or password are refused, the URL is never logged (only the number of findings and whether the AI answered), and only the findings and the AI summary, never the HTML, are cached for 6 hours.
- **The Claude call uses structured outputs** (`output_config.format` with the `AI_SCHEMA` JSON schema) and `effort: low`. `impersonated_brand` uses `anyOf` with `null`, because type arrays are not documented for structured outputs. A `stop_reason` other than `end_turn` (refusal, `max_tokens`) raises `AIStopped`, and the text block is found by type because thinking blocks may come first; both fall back to the rules. `parse_ai` still validates the answer, since a schema guarantees the shape, not the truth.
- **Without `ANTHROPIC_API_KEY` the server still runs:** page analysis returns the rule findings only. A spent budget, an expired key or an API error do the same.
- **Page analysis is measured inside a virtual machine** (`scripts/measure_pages.py`), because the pages are downloaded. The sample is picked on the host, where `phishing.csv` lives, and copied to the VM with `scp` (no shared folder, so the VM sees nothing of the host): up to 200 phishing pages first seen in the last 2 days (one per registered domain, so one campaign cannot fill it), up to 100 benign pages the URL rules already warn about (where page analysis must not add an alarm) and random benign pages up to 200. Only fired rules and points are saved, never the HTML, plus a few page features to explain misses: password and OTP or card fields, text and HTML length (much HTML with little text usually means a page built by JavaScript), protected brands in the title, and the title itself (80 characters; a title starting with `=`, `+`, `-` or `@` gets a leading quote, so a spreadsheet cannot run it as a formula); `pages.csv` and `page_sample.csv` are git-ignored.
- **`benign_vn.txt` grew from 24 to 153 sites on 2026-11-09,** from a compiled list of 639 domains. 471 were already in the benign sets or the allowlist and 29 are in the Tranco top 10,000 (left out, as for the whole benign set). The other 139 were fetched: 124 answered over HTTPS, plus 4 redirect targets (`cand.vn`, `vnptpay.vn`, `greensm.com`, `bkav.com`) and `www.shb.com.vn` (the bare domain did not answer). Eleven sites failed TLS in Python but passed in curl: they send no intermediate certificate, which browsers fetch themselves. Left out: 8 domains that no longer resolve (merged ministries, `bacabank.com.vn`, `citibank.com.vn`; an expired domain can be registered by anyone), 3 with expired or mismatched certificates, `sendo.vn` (no answer) and 2 user-content platforms. Two sections are not Vietnamese (developer tools, sportswear brands); the Vietnamese subset is chosen by suffix, so they do not change it.
- **First live page measurement (2026-11-09, rules only, Ubuntu 26.04 VM):** phishing 138 of 200 pages downloaded, 2 flagged (1.4%: one `page_brand_login`, one `page_asks_otp_card`); benign pages already warned by URL rules 68 of 100 downloaded, 1 flagged (`page_form_external` alone, 20 points, enough to push a yellow page to red); random benign 67 of 100 downloaded, none flagged. Why so little phishing is caught: the faked brands are foreign (Allegro, WhatsApp, Apple, OKX) and `page_brand_login` only knows `brands.json`; 62 of the 138 pages sit on site builders (50 on `pages.dev`, others on `vercel.app`, `lovable.app`, `framer.app`, `github.io`), whose pages are usually built by JavaScript, so the downloaded HTML has no form. Which of the two dominates is not measured yet. 46 of the 62 phishing pages that failed no longer resolved after at most 2 days.
- **Second live page measurement (2026-11-10, rules only, with page features):** phishing 119 of 200 downloaded, none flagged; benign pages warned by URL rules 66 of 100, 1 flagged (`page_form_external` again); random benign 63 of 100, none flagged. The new columns explain the misses. By title, 74 of the 119 downloaded phishing pages no longer show phishing: 31 Cloudflare warning pages ("Suspected Phishing", "Suspected Malware"), 34 error, empty or parked pages, 5 speed-test decoys and 4 Cloudflare bot checks. Of the other 45, about 12 look like live phishing (three "Wallet Connect" crypto drainers, a PayPal login, a fake Polish ticket shop, Polish "ostrzeżenie" warnings, a Brazilian INSS loan scam, Roblox lures), none of them Vietnamese; most of the rest are ordinary small-business pages, which fits cloaking (a decoy for visitors outside the target country) or hacked sites. Only 2 phishing pages had a password field, and 44 had under 200 characters of text. The IPv4 fix removed the `OSError` failures (15 in the first run, 0 now); timeouts are now the main failure.
- **What this means for page analysis:** on these feeds the server sees the aftermath, not the attack. Pages are first seen by the feeds up to two days late, and by then most are taken down, parked or cloaked; a server in another country is shown a decoy. The rules cannot be tuned on this data, and the AI would see the same decoys. Page analysis is worth most in the extension, at the moment the user opens the page, with the page as the user's own browser renders it. The server endpoint stays opt-in and secondary.
- **Page analysis in the first release stays on the server** (decided 2026-11-10): `/v1/analyze-page` with the AI layer, turned on by the user, called only when the URL result is yellow. Running the page rules inside the extension was considered: it reads the page as the user sees it (after JavaScript, no cloaking, nothing leaves the browser), but needs a content script on every site and a JavaScript port of `page_features`. The server path was kept because it is built and tested, and the AI understands threats and money-transfer requests that fixed rules miss.
- **Page analysis must be measured before the public release.** Source: Vietnamese phishing pages copied by hand each day from ChongLuaDao's public listings (URL plus what the screenshot asks for) into the git-ignored `data/raw/chongluadao_daily.csv`, downloaded in the VM on the same day (`measure_pages labelled` picks today's rows, and the report compares what the screenshot asks for with the fields found in the downloaded HTML), with the rules and then with `--ai` once the Console account is funded. On the first 10 pages (2026-11-10 and 11), the URL rules flagged none and the blocklist one: the scams (job tasks, Liên Quân item shops, loans, investment) put the brand on the page, not in the domain name. urlscan.io was ruled out: searching by malicious verdict needs a paid plan, its terms forbid compiling a database without written permission, and a manual look found almost no usable Vietnamese pages. Limit: the VM has a Vietnamese IP, while the production server will run abroad (AWS has no region in Vietnam), so pages shown only to Vietnamese visitors may show the server a decoy; results from the VM are an upper bound.
- **Character features of the domain name were measured and dropped** (2026-11-11, train split only, one entry per registered domain; benign scores from a half of benign train not used to fit the bigram model). Tried: entropy, length, digit ratio, longest consonant run, a letter-digit switch and a character-bigram score learned from benign names, each as a yes/no rule with a threshold set on benign train. Within the yellow budget still free (about 0.3% new benign alarms) the best combination caught 6.6% of the feed phishing the rules miss but only 1.0% of the missed PhishVN phishing; within 0.05% it caught 3.1% and 0.2%. The letter-digit switch separates better (6% of benign names, 20% of missed feed phishing, 27% of missed PhishVN) but is far too common on legitimate sites to use alone. Random-looking names are as common among legitimate sites as among phishing, as the surveys that report 95-99% accuracy on balanced random splits do not show. Of the PhishVN train phishing the rules miss, 73% have names with no usable signal (numbers, random strings, mostly gambling and streaming sites on the NCSC list), 9% are crypto or investment scams, 8% gambling or football, 6% bank names with a typo or prefix (`ibidv`, `vnbidv`, `vayvonvcbank`) and 2% loan scams (`chovaynganhang`). The last two are Vietnamese patterns a rule could target; measure them on validation before adding anything.
- **Page titles are matched without Vietnamese diacritics** (2026-11-12). `brands_in` kept only `a-z0-9`, so "Bảo Hiểm Xã Hội Việt Nam" (the title of a fake social insurance portal from ChongLuaDao) was cut into fragments and named no brand. `strip_accents` decomposes the text (NFD), drops the combining marks and maps `đ` to `d` by hand, since `đ` is a letter of its own in Unicode. Short brands still need a whole word, so "Mô Mô" or "Tí Kì" do not become `momo` or `tiki`. Risk to measure: a provincial social insurance page on another registered domain, with a password field, would now fire `page_brand_login`. Still missing for that page: it asks for a CCCD number.
- **ID number fields count as sensitive, but only with a brand** (2026-11-13). `has_id_number` looks for CCCD, CMND, căn cước, chứng minh, số định danh and hộ chiếu (with and without diacritics) in input names, ids, placeholders and autocomplete values, and joins the password, OTP and card fields in `page_brand_login` and `page_form_external`. It adds no points alone, since real banks and public services ask for it when an account is opened. `passport` and `identity` are left out: account systems use them for a plain user name. Not known yet: whether the fake social insurance portal has a typed CCCD field at all, or only takes the ID card by QR code and photo upload.
- **`resolve_public_ips` returns IPv4 addresses first** (2026-11-09). The VM has an IPv6 address but no IPv6 route to the internet; addresses were sorted as text, so `2a03:...` came before `57.144...`, `follow` tried only that address and failed (`errno 101`, 7 Meta domains among 15 benign failures). `check_tls` and `collect_signals` try two addresses and miss hosts with two IPv6 addresses the same way. The Mac resolves IPv4 only, so `signals.csv` is not affected.
- **`follow` treats broken HTTP as a failed request** (`http.client.HTTPException`, e.g. more than 100 headers, and invalid redirect ports): the first VM run stopped on one phishing page, and the same page would have turned `/v1/analyze-page` into an HTTP 500.
- **Six banks added to `brands.json`, two official domains extended** (2026-11-09): BaoViet Bank, VietABank, LPBank, Nam A Bank, PVcomBank, Kienlongbank; `shopeepay.vn` for Shopee, `vnpt.vn` for VinaPhone (where `vinaphone.com.vn` redirects). Each official domain answered with the bank's own title that day. On validation: false alarms on our benign set 0.165% to 0.160%, on `benign_vn.txt` 3 to 0 (`baovietbank.vn`, `vietabank.com.vn`, `shopeepay.vn`), PhishVN benign unchanged; detection unchanged on feeds (1.036%) and PhishVN (18.5%), since no sample targets these banks yet. ABBank was left out: `abbank` is close enough to `a-bank.com.ua` and `rabobank.nl` to raise two new false alarms.
- **The Python code is the reference for the JavaScript port**, including the deviations from the guide (`contains_brand`, aliases, Unicode handling, English reasons and levels).
